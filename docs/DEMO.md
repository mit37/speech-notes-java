# Demo recording script

**Who records it:** Mitansh (STANDARDS §5 — GUI projects deserve a screen recording, and a machine
with a display and a microphone is needed for this one; the build machine has neither).
**Target length:** 90–120 seconds, one take is fine. **No voice-over required** — captions are
enough, and the transcript on screen is the point.

## Before you hit record

```bash
./gradlew build                         # green build, tests included
scripts/test_count.sh                   # the test count the caption can quote, generated
scripts/download_model.sh               # 40 MB Vosk model, checksum-verified
./gradlew installDist                   # plain launcher, no Gradle wrapper around the exit code
```

Then check the offline claim you are about to make:

1. **Turn Wi-Fi off.** The transcription half must keep working with the network gone. Screenshot Q&A
   will report `GEMINI_API_KEY` as missing — that is the honest answer, not a bug.
2. Note the model path shown in the window title/status line, e.g.
   `models/vosk-model-small-en-us-0.15`.
3. Have `eval/audio/lecture-01-caching.wav` ready to play in another window if you do not want to
   speak live.

## Shot list

| # | What to show | What the captions say |
|---|---|---|
| 1 | Terminal: `./gradlew build` finishing green | "Tests, Spotless, Checkstyle — all local" |
| 2 | Terminal: `bash scripts/run_eval.sh` scrolling the table | "WER and real-time factor, generated by this script" |
| 3 | Terminal: `./gradlew installDist && build/install/speech-notes-java/bin/… --file eval/audio/lecture-01-caching.wav` | "The same pipeline the window uses, offline" |
| 4 | Start the window: `… --ui` (or `scripts/package_app.sh` output) | "JavaFX UI, no key, no account" |
| 5 | Press **Record**, speak two sentences (or play the fixture near the microphone), show the transcript filling in as you talk | "On-device Vosk: partial results appear as you speak" |
| 6 | Press **Pause**, keep talking, press **Resume** | "Pause really stops capturing" |
| 7 | Press **Stop**: the Notes pane fills with headings, bullets, key terms, action items | "Rule-based notes, offline — no key, no upload" |
| 8 | Type a question in the box, then press **Ctrl+Shift+S** (the hotkey is in the button's tooltip and the window title); show the answer (with a key) or the refusal line (without) | "Screenshot Q&A needs Gemini; offline it says so instead of guessing" |
| 9 | Terminal: `--export both` run, then open `notes.pdf` next to `notes.md` | "Markdown and PDF from the same notes" |
| 10 | Final caption card | "Transcription: always offline. Gemini: optional, capped, key-gated." |

## If something goes wrong on camera

- **No microphone permission / no device:** use the `--file` mode in shot 3 and say plainly in the
  caption that mic capture was tested with a fake source in CI but the live demo needs hardware.
- **Gemini returns an error:** keep it in the take. The project's rule is to show what happened,
  including a refused request, rather than cutting to a happy path.
- **Recogniser mishears a word:** do not cut it either — the README quotes the same class of mistake
  (`cashing` for `caching`), and showing it is the honest version of a demo.

## After recording

`v2.0.0` is already published, so this is an edit of an existing release rather than a new one —
published releases still take assets.

1. Encode the take as `speech-notes-java-demo.mp4` (MP4/H.264 plays inline on the release page; a raw
   `.mov` downloads instead of playing).
2. Open <https://github.com/mit37/speech-notes-java/releases/edit/v2.0.0> and drag the file into the
   assets box. No new tag, no new release.
3. `README.md`: add the link to the Status paragraph at the top — the one sentence that says the
   recording is the last thing still open — and next to the numbers in Results that it narrates.
4. `docs/PLAN.md`: tick the **Demo recording** box under M8 and drop the sentence saying the demo is
   still to come.
5. The video lives in the release, not in git: a binary like that does not belong in a text diff, and
   the repo stays at ~7 MB while the release carries the heavy files.
