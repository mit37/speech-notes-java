This session is about testing your own code. First, a test that never fails is a test that never checks anything, so break the code once and watch it fail. Second, test the rule, not the framework, or your suite becomes a slower version of the framework. Third, keep the suite fast enough that you run it before every commit. Our build runs two hundred and thirty tests in eleven seconds, and that number matters more than the coverage badge. Action: add a failing test for the bug you just fixed. Finally, treat a flaky test as a defect, not as weather.
