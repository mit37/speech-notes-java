This lecture explains database indexes. First, an index makes reads faster and writes slower, so count the writes before you add one. Second, the column order in a composite index decides which queries it can serve. Third, read the query plan instead of guessing, because the planner sees statistics that you do not. A table scan is not automatically a problem when the table is small. Action: capture the query plan for the slow report before you change anything. Finally, an index is a promise about how data is read, and promises expire as the data changes.
